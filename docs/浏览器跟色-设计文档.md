# 浏览器画面同步（网页哔哩）— 设计文档

> 状态：**P2 Safari 扩展工程已落地（需本机 Xcode Run 启用）**  
> 日期：2026-09-06  
> 关联：[`交接文档.md`](../交接文档.md) §11 · 扩展见 [`browser-extension/README.md`](../browser-extension/README.md)

---

## 1. 一句话目标

用户用 **Chrome / Safari 打开 B 站（或其它网页视频）** 观看；**易来控制 App 不负责播放**，只接收播放态并截浏览器窗口取色，经现有 UDP 热路径驱动挂灯跟色/跟亮度。行为对齐 IINA：**暂停停跟、退出还原**。

---

## 2. 已锁定决策

| # | 议题 | 决定 |
|---|---|---|
| D1 | 形态 | **浏览器播 + App 跟色**；不做 Electron 内嵌 B 站播放器 |
| D2 | 播放态 | **必须**：暂停停跟；退出/关页按 `on_exit` 还原（与 IINA 同策略） |
| D3 | 浏览器 | **Chrome + Safari** 优先（同逻辑、分端打包） |
| D4 | 与 IINA | **各自独立整套参数**（开关/通道/平滑/区域/退出等）；上下分栏排列；可同时启用 |
| D5 | 站点范围 v1 | 以 **bilibili.com / bilibili.tv** 为主；架构按「网页媒体源」泛化，便于后加站点 |
| D6 | 不做 | 内嵌播放器、替代 B 站客户端、云端、多灯组、音乐律动 |
| D7 | 弹幕 vs 取色 | **用户手动关闭弹幕**；不自动关弹幕、不采 `<video>` 帧、不做近白过滤等抗弹幕算法（优先性能/功耗） |

---

## 3. 不做 / 边界

| 项 | 说明 |
|---|---|
| 不内嵌 WebView 播片 | App 仍是控灯 + 同步中枢 |
| 不解析视频流 / 不解 DRM | 只截屏取色 + 扩展上报状态 |
| 不保证非 B 站站点 | v1 扩展匹配 bilibili；窗定位按浏览器进程，全屏其它站可作为后续 |
| 不自动安装系统扩展 | UI 引导用户安装；Safari 需额外启用 |
| 热路径仍禁止滥打 TCP | 跟色/亮度继续 UDP；exit 动作走 TCP（与现网一致） |
| 不处理弹幕干扰 | 截屏会带上弹幕层；**由用户在 B 站手动关弹幕**。不做扩展一键关弹幕、抽 video 帧、去近白像素等（省 CPU/电） |

### 3.1 弹幕说明（给用户 / UI 文案）

取色截的是屏幕合成画面，弹幕叠在视频上会进采样，密弹幕易导致灯色偏白、发花。

- **推荐**：开启浏览器同步跟色时，在播放器里 **关闭弹幕**（或透明度调到最低）  
- **本产品**：不代为开关弹幕，也不为抗弹幕加重取色路径  
- UI / 安装说明中应用一句话提示上述习惯即可

## 4. 用户故事与验收场景

### 4.1 主路径

1. 用户安装 Chrome 或 Safari 扩展「Yeelight Bar Sync（Web）」  
2. 控制窗将同步源设为 **浏览器**，打开同步总开关  
3. 在浏览器打开 B 站视频，**手动关闭弹幕**后播放 → 氛围灯跟画面色；主灯/氛围亮度按现有通道配置  
4. **暂停** → 停止推新色（默认 `on_pause=keep_last`，保留最后一帧色）  
5. **继续播放** → 恢复跟色  
6. **关闭标签 / 离开播放页 / 浏览器退出**（扩展报 exit）→ 执行 `on_exit`（`ambient_mode` / `restore` / `off_ambient`）  
7. 切回同步源 **IINA** → 浏览器 hook 被忽略；IINA 行为不变  

### 4.2 验收清单（实现后勾）

- [ ] `sync.source=browser` 时，Chrome 全屏 B 站跟色稳定  
- [ ] Safari 同上（至少非全屏 + 全屏各测一次）  
- [ ] 暂停后颜色不再随广告/暂停帧乱跳（keep_last）  
- [ ] 关播放页或关浏览器后，灯按 `on_exit` 正确动作（注意 TCP 配额）  
- [ ] `sync.source=iina` 时浏览器扩展上报不影响同步  
- [ ] 扩展未安装：UI 有明确提示；可选「仅跟窗」兜底（见 §9）不承诺 pause/exit  
- [ ] 多显示器：跟视频所在屏上的浏览器窗（`display_id` / 窗几何）  
- [ ] IINA 原有同步回归通过  
- [ ] UI 或说明中有「建议关闭弹幕」提示（不自动关）

## 5. 架构

```
┌──────────────────┐   HTTP    ┌─────────────────────────┐
│ Electron UI      │◄─────────►│ FastAPI :8787           │
│ 同步源 / 引导安装 │          │  media hook + SyncEngine │
└──────────────────┘           └───────────┬─────────────┘
                                           │
     ┌─────────────────────┐               │
     │ IINA 插件（现有）    │──/api/iina/───┤
     └─────────────────────┘               │
                                           │
     ┌─────────────────────┐               │
     │ Chrome 扩展         │──/api/media/──┤
     │ Safari 扩展         │   hook        │
     └─────────────────────┘               │
                                           ▼
                                 ┌──────────────────┐
                                 │ 取色 capture     │
                                 │ Chrome/Safari 窗 │
                                 │ → UDP 跟色       │
                                 └────────┬─────────┘
                                          ▼
                                     挂灯 LAN
```

**原则：**

- 播放态来源可插拔：`iina` | `browser`（未来可加 `fullscreen-app`）  
- 取色与 UDP 管线复用 `SyncEngine`；只扩展「找谁的窗」和「听谁的 hook」  
- 扩展只报状态，不控灯；控灯权限仍在本机 API

## 6. 媒体源模型

### 6.1 配置

在 `config.sync` 增加（名称以实现为准，建议如下）：

```json
{
  "sync": {
    "enabled": true,
    "source": "iina",
    "browser": {
      "owners": ["Google Chrome", "Chromium", "Microsoft Edge", "Safari", "Orion"],
      "match_hosts": ["www.bilibili.com", "m.bilibili.com", "www.bilibili.tv"],
      "require_extension": true
    },
    "on_pause": "keep_last",
    "on_exit": "ambient_mode",
    "exit_mode": "movie"
  }
}
```

| 字段 | 含义 |
|---|---|
| `source` | `iina` \| `browser`；互斥，UI 单选 |
| `browser.owners` | Quartz `kCGWindowOwnerName` 白名单（Chrome/Safari 等） |
| `browser.match_hosts` | 扩展侧 URL 匹配；服务端可只做日志/校验 |
| `browser.require_extension` | `true`：无新鲜 hook 则不跟色；`false`：允许纯窗跟色兜底 |

### 6.2 统一播放态（逻辑结构）

对齐现有 `IinaStatus`，建议抽象为 `MediaStatus`（或 browser 侧平行结构 + engine 分支）：

| 字段 | 说明 |
|---|---|
| `running` | 媒体会话是否仍有效（浏览器进程在 + 扩展认为在播放页） |
| `playing` | 正在播（未 pause、未 ended） |
| `pause` | 暂停 |
| `event` | `play` / `pause` / `playing` / `ended` / `seek` / `visibility` / `exit` / `heartbeat` 等 |
| `title` / `url` | 可选，调试用；勿持久化隐私敏感完整 URL 到日志默认级别 |
| `fullscreen` | 可选，辅助选窗 |
| `seek` | 可选；网页 seek 时清空平滑重采（对齐 IINA） |

**TTL：** 与 IINA 插件类似（约 2～3s）。心跳超时且进程仍在 → 视为无扩展或页休眠，按 `require_extension` 决定停跟或仅跟窗。

### 6.3 Engine 会话语义（对齐 IINA）

| 条件 | 行为 |
|---|---|
| `source` 匹配且 `playing` | 取色 + UDP 推送；标记本轮 `_sync_session` |
| `pause` / 非 playing | **停跟**；`on_pause=keep_last` 不改灯色 |
| `running` 从 true→false，或 `event=exit` / `ended`（可配置是否当 exit） | 若本轮跟过色 → 执行 `on_exit` |
| `source` 切换 | 先对旧源做一次 exit 语义（若在 session 中），再听新源 |

**建议：** B 站「视频 ended」默认走与 exit 相同策略（或单独 `on_ended`，v1 可与 `on_exit` 合并）。

## 7. 窗口定位（取色）

### 7.1 现状

`find_iina_window` 硬编码 `kCGWindowOwnerName == "IINA"`，按面积选最大窗。

### 7.2 目标

```
find_media_window(source, *, display_id, owners?, hint?)
```

| source | 策略 |
|---|---|
| `iina` | 保持现逻辑（可内部仍调原函数） |
| `browser` | Owner ∈ `browser.owners`；过滤过小窗、设置窗、DevTools；优先：扩展上报的 fullscreen / 标题含「哔哩」或视频标题；否则同屏最大内容窗 |

### 7.3 全屏与标题栏

- 浏览器全屏时窗界 ≈ 显示器；`region=window/top/full` 语义保持，**标题栏启发式（约 36px）在全屏时应关闭或减小**，避免裁错  
- Safari / Chrome 有无标签栏、画中画：v1 **不跟 PiP 小窗**（面积阈值排除）；主视频窗优先  
- 无匹配窗：`window` 区域降级到所选显示器 top/full（与现 IINA 无窗降级一致），并在 `/api/sync/status` 标明 `capture.source`

### 7.4 Owner 名注意（macOS）

实测为准，文档预留常见值：

- `Google Chrome`、`Chromium`、`Microsoft Edge`、`Brave Browser`  
- `Safari`  
- 国产双核若有需求再加（非 v1）

## 8. API 设计

### 8.1 兼容策略

| 路由 | 动作 |
|---|---|
| `POST /api/iina/hook` | **保留**；仅当 `source=iina`（或未设 browser）时驱动同步；内部可写入统一 media 状态且标记 `provider=iina` |
| `POST /api/media/hook` | **新增**；body 带 `provider: "browser"`；仅当 `source=browser` 时驱动同步 |
| `GET /api/media` | **新增**；当前有效媒体状态 + provider + 是否过期 |
| `GET /api/iina` | 保留，便于旧 UI/排障 |
| `GET /api/sync/status` | 增加 `source`、`media`、浏览器窗 meta |
| `PATCH /api/config` | `sync.source`、`sync.browser.*` |

### 8.2 `POST /api/media/hook` Body（草案）

```json
{
  "provider": "browser",
  "event": "play",
  "running": true,
  "playing": true,
  "pause": false,
  "url": "https://www.bilibili.com/video/BVxxxx",
  "host": "www.bilibili.com",
  "title": "……",
  "fullscreen": true,
  "position": 12.3,
  "duration": 600.0,
  "seek": false,
  "ts": 1725600000
}
```

校验：

- 仅监听 `127.0.0.1`（已有）  
- 可选：校验 `host` ∈ `match_hosts`，否则忽略 playing  
- `event=exit` 时强制 `running=false, playing=false`  

IINA hook 可不改客户端；服务端适配层把两边归一。

## 9. 浏览器扩展

### 9.1 目录建议

```
browser-extension/
├── README.md                 # 安装说明（Chrome / Safari）
├── shared/                   # 共用逻辑（尽量）
│   ├── hook.js               # 组 payload、POST 本地 API
│   ├── detect.js             # B 站播放器状态探测
│   └── constants.js          # API base、host 列表
├── chromium/                 # Chrome MV3
│   ├── manifest.json
│   ├── background.js
│   └── content.js
└── safari/                   # Safari Web Extension 包装
    └── （Xcode 工程或转换说明）
```

### 9.2 权限与匹配

- `host_permissions` / `matches`：`*://*.bilibili.com/*`、`*://*.bilibili.tv/*`  
- 访问 `http://127.0.0.1:8787/*`（Chrome：可能需 `optional_host_permissions` 或扩展页配置；**本地 HTTP 需在 manifest 明确允许**）  
- 最小权限：不读其它站点；不上传云端  

### 9.3 探测策略（B 站）

页面 DOM/播放器 API 易变，采用**多层降级**：

1. **优先**：`<video>` 的 `play` / `pause` / `ended` / `seeking` / `timeupdate`（节流）  
2. **辅助**：全屏 API、`document.visibilityState`（切后台可报 pause 或单独 visibility，产品定：v1 **切走标签视为 pause 停跟**）  
3. **心跳**：播放中每 ~1s `heartbeat`，刷新服务端 TTL  
4. **退出**：`pagehide` / `beforeunload`、content script 卸载、扩展检测到匹配 Tab 关闭 → `exit`  
5. **URL 变化**：离开 `/video/` `/bangumi/` 等播放路径 → `exit` 或 `idle`  

不依赖非公开内部全局变量作为唯一路径，避免一改版全挂。

### 9.4 Chrome vs Safari

| | Chrome | Safari |
|---|---|---|
| 形式 | Manifest V3，用户加载已解压目录或打包 crx（分发另说） | Web Extension，需 App 包装或 `safari-web-extension-converter`；用户在 Safari 设置里启用 |
| 安装脚本 | `scripts/install-chrome-extension.md` 或打开 `chrome://extensions` 引导 | `scripts/` + README 逐步说明；可后续做 macOS 包装 App |
| 本地 API | 注意 CORS：FastAPI 对 hook 已同机；扩展 fetch 需服务端 **CORS 允许扩展 Origin** 或用 background 无 CORS 限制策略（MV3 service worker `fetch` 通常可绕过页面 CORS，以实测为准） |

### 9.5 安全

- 只绑 localhost  
- Hook 不包含 cookie / 登录态  
- URL 可只传 path + host，query 可剥离

| 风险 | 对策 |

## 17. 摘要（给执行用）

**做：** Chrome/Safari 扩展报 B 站播放态 → 本地 API → SyncEngine 截对应浏览器窗 → UDP 跟色；暂停停跟、退出按 `on_exit`；与 IINA 源互斥。  

**不做：** App 内嵌播 B 站；自动关弹幕 / 抗弹幕重算法 / 采 video 帧（用户手关弹幕，保性能功耗）。  

**顺序：** 窗定位与 source 切换 → Chrome 扩展闭环 → Safari → 打磨。
