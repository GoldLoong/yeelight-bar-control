## 1. 一句话目标

在现有 **IINA / 浏览器** 跟色之外，增加第三种媒体源 **「屏幕」**：对整屏、前台窗口或用户框选区域连续取色，经现有 UDP 热路径驱动挂灯。三源**各自独立整套参数**，运行时通过**可拖动优先级列表**仲裁，**同一时刻只跟一路**。

## 3. 不做 / 边界

| 项 | 说明 |
|---|---|
| 不混色 | 禁止 IINA+浏览器+屏幕同时往灯推色 |
| 不读应用内 API | 不解析游戏/网页 DOM；只截屏采样 |
| 不替代扩展 | 浏览器精准 pause/exit 仍靠扩展；屏幕源用自己的可跟规则 |
| 热路径仍 UDP | 跟色/亮度 UDP；exit 收尾走 TCP（与现网一致） |
| 系统权限 | 依赖 macOS **屏幕录制**权限；无权限时 UI 明确提示 |

## 4. 用户故事与验收场景

### 4.1 主路径

1. 用户打开同步页，看到优先级列表（默认可拖：IINA、浏览器、屏幕）与三个可折叠源面板  
2. 打开 **屏幕** 开关，取色目标默认 **前台窗口**，按需改整屏或框选自选区域  
3. 勾选可跟条件组合；配置通道 / 平滑 / 取色屏幕 / 退出策略（均属屏幕自己的一套）  
4. 当前无更高优先级源在跟时 → 氛围灯（及已开通道）跟随屏幕取样色  
5. IINA 开始播放且优先级更高 → **立刻切到 IINA**；IINA 暂停不可跟 → 若浏览器可跟则跟浏览器，否则回屏幕（若仍可跟）  
6. 锁屏 / 息屏 → 屏幕源按自己的 `on_exit` 收尾灯效  
7. 前台切到易来控制窗 → 不跟本窗，跟上一前台或退整屏  

### 4.2 验收清单（实现后勾）

- [ ] 三源均可独立开关，参数互不覆盖  
- [ ] 拖动优先级后，活跃源按新顺序重算并切换  
- [ ] 默认顺序 IINA > 浏览器 > 屏幕  
- [ ] 整屏 / 前台窗 / 自选区域三种目标均可工作；默认前台窗  
- [ ] 遮罩框选可保存并再次进入仍有效  
- [ ] 可跟条件多选组合生效（见矩阵 §6.2）  
- [ ] 锁屏/息屏触发屏幕 `on_exit`（氛围模式 / 恢复 / 关氛围灯）  
- [ ] 前台为本 App 时跳过并降级  
- [ ] 多屏下「取色屏幕」约束整屏与框选  
- [ ] 平滑默认接近 IINA，可调  
- [ ] IINA / 浏览器原有行为回归通过  
- [ ] 无屏幕录制权限时有明确提示，不静默失败

## 5. 架构

```
┌──────────────────┐   HTTP    ┌─────────────────────────┐
│ Electron UI      │◄─────────►│ FastAPI :8787           │
│ 优先级拖拽        │           │ config / sync status    │
│ 手风琴三源面板    │           └───────────┬─────────────┘
│ 框选遮罩层        │                       │
└──────────────────┘                       ▼
                                 ┌─────────────────────┐
                                 │ SyncEngine          │
                                 │ priority 仲裁        │
                                 │ iina | browser |    │
                                 │ screen              │
                                 └───────────┬─────────┘
                                             │ mss / Quartz
                                             ▼
                                 ┌─────────────────────┐
                                 │ capture             │
                                 │ display / front win │
                                 │ / user rect         │
                                 └───────────┬─────────┘
                                             │ UDP
                                             ▼
                                        挂灯氛围/亮度
```

原则：

- 扩展 / IINA 插件仍只报状态；屏幕源由本机引擎根据目标与可跟条件判定  
- 仲裁在 Engine 内完成；UI 只改 `priority` 与各源配置

## 6. 优先级与「可跟」语义

### 6.1 优先级列表

- 配置：`sync.priority: ["iina", "browser", "screen"]`（高 → 低）  
- 默认即上列顺序  
- UI 拖拽即时 PATCH，写回配置  
- **活跃源** = 第一个满足「enabled ∧ eligible（可跟）」的源  
- 高优先级从不可以 → 可跟：立即切换（建议短暂清平滑，避免拖尾）  
- 高优先级从可跟 → 不可跟：落到下一可跟源；若无 → 停跟并执行**刚失去可跟的那一路**的退出策略（屏幕锁屏场景明确走屏幕 `on_exit`；IINA/浏览器沿用现有 pause/exit）

### 6.2 屏幕「可跟」条件（多选组合）

配置建议：`sync.screen.eligibility` 为字符串数组，例如：

| 选项 key | 含义 |
|---|---|
| `always` | 开关打开即视为可跟（仍受其它勾选项约束时可并存） |
| `target_valid` | 目标有效才跟：有指定屏 / 有可用前台窗 / 已保存框选区域 |
| `fullscreen_only` | 仅当取色目标处于全屏（或近全屏）时才跟 |

**组合规则（建议实现）：**

- 未勾任何项：等价于仅 `target_valid`（安全默认，避免空采）  
- 多选时为 **AND**：全部勾中的条件都满足才可跟  
  - 例：`target_valid` + `fullscreen_only` → 目标有效且全屏  
  - 若同时勾 `always` 与其它：以 **更严的其它条件为准**（`always` 不覆盖 `target_valid` / `fullscreen_only`）；或产品上禁止 `always` 与其它同勾——**实现时采用：有效集合 = 所选条件的 AND，忽略单独的 always 若还存在其它条件**  
- **锁屏 / 息屏 / 无法采集**：一律视为不可跟，并触发屏幕 `on_exit`（D6），不依赖上述勾选  

> 实现备注：macOS 锁屏检测可用屏幕休眠通知 / 采集失败连续 N 帧等启发式；需在实现时定可靠信号并写进代码注释。

### 6.3 前台窗口降级（D7）

排除（至少）：本 App（Electron / 易来挂灯）、过小窗口（面积阈值，如 < 总屏 5% 或宽高过小）。

顺序：当前前台 → 若命中排除 → **上一前台**（引擎缓存）→ 仍不可用 → **退回整屏**（使用当前 `display_id` 指定屏）。退回整屏时状态行提示「已降级为整屏」。

## 7. 配置草案

在现有 `sync.iina` / `sync.browser` 旁增加 `sync.screen`（与 `SourceSyncSettings` 同级扩展）：

```json
{
  "sync": {
    "enabled": true,
    "priority": ["iina", "browser", "screen"],
    "iina": { "...": "现有字段" },
    "browser": { "...": "现有字段" },
    "screen": {
      "enabled": false,
      "channels": {
        "ambient_color": true,
        "main_brightness": false,
        "ambient_brightness": false
      },
      "display_id": null,
      "capture_target": "front_window",
      "region": "window",
      "user_rect": null,
      "eligibility": ["target_valid"],
      "color_smooth": 0.20,
      "main_bright_smooth": 0.20,
      "ambient_bright_smooth": 0.20,
      "base_main_bright": 50,
      "base_ambient_bright": 40,
      "main_bright_range": 5,
      "ambient_bright_range": 30,
      "on_exit": "ambient_mode",
      "exit_mode": "ambient_mode"
    }
  }
}
```

| 字段 | 说明 |
|---|---|
| `capture_target` | `display` \| `front_window` \| `user_rect` |
| `user_rect` | `{ display_id, left, top, width, height }` 屏幕坐标；框选写入 |
| `eligibility` | 见 §6.2 |
| `color_smooth` 等 | 默认贴近 IINA（0.20） |
| `on_exit` | **仅屏幕自己的**收尾；与 iina/browser 独立 |

旧配置无 `priority` / `screen` 时：迁移默认 `priority=["iina","browser","screen"]`，`screen.enabled=false`。

API：沿用 `PATCH /api/config`；`GET /api/sync/status` 增加 `priority`、`screen_enabled`、`active` 源含 `"screen"`、屏幕目标/降级提示。

框选：建议 `POST /api/sync/screen/region` 由 UI 在遮罩确认后提交矩形；或直接 PATCH `sync.screen.user_rect`。

## 8. 取色实现要点

| 目标 | 做法 |
|---|---|
| 整屏 | 用 `display_id` 对应显示器 bounds，按现有 `region`（top/full/window 语义可复用或简化为整屏中央条带）采样 |
| 前台窗口 | Quartz 前台窗几何；应用 D7 降级 |
| 自选区域 | 使用保存的 `user_rect`；无效则 `target_valid` 失败 |

颜色处理：第一版可用 **非 vivid** 或轻度 boost（接近 IINA，避免浏览器曾用过的过饱和）。

权限：无屏幕录制权限时 `eligible=false`，UI 引导系统设置。

## 9. UI 设计

### 9.1 顶栏：优先级

- 可拖拽三项：IINA / 浏览器 / 屏幕  
- 每项展示：名称、开关态小点、是否「正在跟」、一行状态（播放中 / 待命 / 已关闭）  
- 正在跟的项高亮  

### 9.2 手风琴面板

- 一次主要展开一个源；展开区内容对齐现有源面板：开关、通道、平滑、取色屏幕、区域/目标、退出  
- **屏幕**面板额外控件：  
  - 取色目标：整屏 / 前台窗口 / 自选区域  
  - 「框选区域」按钮 → 进入遮罩  
  - 可跟条件：多选 checkbox  
- 折叠时仍可看到该源一行摘要状态  

### 9.3 框选遮罩

- 全屏（或跨屏）半透明层，拖拽矩形，显示尺寸，确认 / 取消  
- 确认后写入 `user_rect` 并可选自动把 `capture_target` 设为 `user_rect`  
- Electron：可用全屏透明 BrowserWindow 或原生层；需处理好与托盘窗焦点
